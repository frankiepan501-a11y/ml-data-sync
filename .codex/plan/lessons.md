# 经验记录

## 2026-08-11

- 手工补齐一次报表不等于系统已经修好；验收通过后必须把同一规则接入生产生成器，未来月份才能自动复用。
- ERP 品名和类目只适合展示与归类，不能替代 ERP SKU 作为采购成本关联键。
- 财务字段映射遇到未知或冲突时必须 fail-closed（停止并报错），不能静默写空值或 0。
- “接口写入成功”不等于报表可交付：三张 Sheet 和公式都要回读；COMPLETE 必须最后写，否则失败重试会误认半成品。
- 进程内锁只能保护单实例；生产回调的防重和退回打断必须另有 SQLite 持久闸，并在外部状态写入前二次核验。
- 只保存“最后一个按钮 key”无法拦住更早卡片的延迟重放；动作去重必须保留完整完成历史，同时区分“已完成不可重放”和“失败后允许重试”。
- 无效旧卡如果先领取新的动作序号，会误伤正在执行的有效确认；因此 message_id/终稿状态校验必须放在 claim 之前，claim 后的竞态复查发现无效时要丢弃占位。
- 成本重算不是一次原子写入；只在结尾拦截状态还不够，整个逐行写入期间必须对确认动作可见并持续阻断。
- 部署验证不能只看 `RUNNING` 和 `/health=200`；必须用 `commit=false` 业务预演验证真实凭据、权限和数据源。代码里的 env 回退名称不能靠历史记忆，要对照当前 Zeabur 变量名称并实测目标 Base 权限。
