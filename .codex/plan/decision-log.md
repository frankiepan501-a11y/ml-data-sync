# 决策日志

## 2026-08-11：ERP 映射与生成闸

- 决策：采购成本关联继续使用 `ERP SKU`，不允许改成品名或类目关联。
- 原因：名称和类目会改名或重复，SKU 才是财务成本的稳定机器关联键。
- 决策：展示字段按精确优先级匹配：产品信息维护表 ERP SKU → 产品采购成本台 ERP SKU → 分销报价单 SKU。
- 决策：同优先级一对多冲突、名称/分类为空或未命中时，整份月报停止生成。
- 原因：财务报表不能把未知值写成空白或 0 后继续流转。
- 决策：自动生成挂在“财务确认终稿”之后，重复触发必须幂等。
- 原因：减少 Frankie 和财务的重复操作，同时避免未确认数据提前生成正式表。
- 决策：完成标记只能在主表、数据源、检查三张 Sheet 全量回读通过后写入；月份生成权用 SQLite 唯一记录跨进程锁定。
- 决策：完成标记包含业务内容哈希。数据未变则复用，数据或 ERP 映射变化则刷新原生成器报表，不创建重复同名表。
- 决策：广告抓取失败、退回、重算会在等待本地月份锁前取消持久生成权；财务终态写入前再次核验状态、按钮动作和生成记录。
- 决策：飞书月结动作 key 用 SQLite 保留完整处理历史，不再只依赖状态表里的“最后一个 key”；完成动作永久防重，失败动作允许原卡重试，旧卡 message_id 和财务终态另做状态保护。
- 决策：同月不同按钮动作按 SQLite 自增顺序裁决，只有最后领取的动作可写状态；领取后任何未处理异常都必须把该动作退回 `failed`，不能留在 `processing` 等 30 分钟。
- 决策：飞书“最后按钮动作Key”只作审计展示，不参与并发先后判断；动作 key 与最终状态在 SQLite finalization guard 内一起写。成本重算先算数据，月结状态必须等最新动作 guard 后再提交。
- 决策：成本重算的逐行写入另设 SQLite 持久工作标记；标记完成前不允许运营/财务确认。
- 决策：已知过期卡片必须在领取动作顺序前拦截；如领取后二次校验才发现过期，且未做业务写入，则删除该无效占位，避免污染当月动作顺序。
