# 2026-09 巴西本土店账单分页短暂不一致

## 问题

9月巴西本土店月度预览返回502。Zeabur运行日志在账单阶段明确记录：`billing details remaining total mismatch key=2026-09-01 expected=950 actual=200`。这说明该次接口页数与上一页计数不一致；原逻辑立即停止，保护了报表免于漏计费用。后续只读抽样同一账期的前五页，官方接口返回总数4100，依次剩余3100、2100、1100、100，页数为1000、1000、1000、100；第六页遇429，因此这次抽样不能证明完整账单已取齐。

## 最小修复

`app/billing.py` 在页数不一致时对**同一游标**最多重读两次，短暂退避；一致才消费该页。仍不一致则继续报错并禁止写报表，不跳页、不把缺失费用当0。`app/main.py` 为月度同步各关键阶段记录耗时，便于区分订单缓存、领星、广告、账单、访客和运费耗时，不记录令牌或明细。依据[美客多官方账单 API 分页说明](https://developers.mercadolivre.com.br/pt_br/guia-para-imoveis/boas-praticas-para-o-consumo-das-apis-de-relatorios-de-faturamento)，账单详情按`last_id → from_id`顺序分页；本次保留原有计数检查，避免在尚未完成官方原件A/B核对前放宽完整性要求。

## 验证与边界

- 回归覆盖一次异常后恢复、连续三次异常仍停止；全套262项测试通过。
- 这只能修正短暂不一致，不能保证9月巴西店同步已完成。网关超时、429、两家本土店官方原件缺失仍需单独处理；在完整预览与A/B通过前不写两家本土店9月正式行。
