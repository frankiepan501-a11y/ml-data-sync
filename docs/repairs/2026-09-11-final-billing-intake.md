# 最终账单核销：第一阶段（未上线）

## 边界

2026-09-11 用户确认：自动收集、核对和生成差异，运营与财务依次确认；不自动重算提成、不补扣工资，差异处理由财务决定。保留已确认经营暂结版。

## 本阶段改动

- `app/final_billing.py`：巴西/MX3官方 REPORT 按精确列名读取，保留费用原始正负号及返还关联编号；文件 SHA256 和来源行号可追溯。
- 费用编号重复内容一致时只计一次，内容冲突时拦截。缺失金额不当作0，不猜日期日/月顺序，不接受可能丢失精度的长数字编号。
- 已结束账期必须按官方起止日期覆盖自然月，缺少单据完整性或正式结束证据时不通过。不能由最早/最晚费用日期推断覆盖。
- 独立来源逐费用编号、币种、日期、金额、退款关联等核对，输出差异及证据版本指纹。
- 所有读取和比较均不会写报表、设置 AB 通过、修改月结状态或发布公司汇总。

## 独立确认记录与原卡反馈保存

新增 `app/final_reconciliation.py`、`tests/test_final_reconciliation.py`。核销批次与经营暂结分开；经营基准锁定，资料变化生成新版本并阻止旧卡确认。正式批次要求不同的运营、财务确认人，按顺序确认；财务必须填写差异处理意见。财务确认仅记为approved，不冒充报表已发布。

确认与原卡更新待办在同一个数据库事务中保存。服务重启后可继续读取待办，重复点击不重复生成；只有原卡更新成功后才由内部执行器登记完成。此处只保存待办，尚未接入飞书PATCH执行器，不能视作原卡已能自动更新。
