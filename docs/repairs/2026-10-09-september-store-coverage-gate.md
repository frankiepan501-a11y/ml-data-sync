# 2026-09 月结缺店时禁止进入经营确认

## 问题

9 月 CBT 官方原件写入后，SKU 表只有 CBT 17 行；巴西本土店和墨西哥本土 3 店仍为 0 行。原月结审计只检查“有行且无成本缺口”，在 CBT 头程成本补齐后，可能把单店数据误判为“待运营确认”，触发不完整报表的确认流程。

## 修复

`app/ml_close.py` 针对 `month_2026-09` 固定核对三家应覆盖店铺：CBT-FULL、巴西 AIRSOFT、本土 3 店 DISTRIBUIDOR VALMIGOZ。缺任一家时保留“待数据同步”，`operating_ready=false`，并在审计结果列出 `missing_stores`。本次只保护 9 月事故范围，不重写历史月份规则。

## 验证与边界

- 新回归用例先复现单店错误进入“待运营确认”，修复后通过；全套测试 257 项通过。
- 这是经营确认放行门；不能替代三店官方原件与 API 自动计算逐字段 A/B、采购/头程成本核对，也不更新正式索引或公司汇总。
- 只有三店数据齐全且其他审计条件通过后，既有梁俊辉→林纯子确认流程才可继续。
