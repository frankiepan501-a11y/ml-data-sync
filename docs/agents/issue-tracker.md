# Issue tracker: GitHub

Issues and specs for this repo live as GitHub issues. Infer the repository from `git remote -v` and use authenticated GitHub tooling.

## Conventions

- Create, read, comment on, label, and close issues with authenticated GitHub CLI/API calls.
- Do not create a remote issue merely for a narrow production hotfix unless the user asks or the work must continue across sessions.
- Pull requests are not a triage request surface by default.
- If authenticated GitHub tooling is unavailable, keep the task in the local project plan rather than attempting anonymous writes.
